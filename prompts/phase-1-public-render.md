1. **Inspect first.** Read `mkdocs.yml` in full and note: the theme (is Material already in use?), whether search is enabled, and anything already set for the footer. Also read `.github/workflows/` to find how the repo currently deploys (if a workflow already builds and deploys the site, note its trigger and target branch). Report what you found before changing anything. Do not assume anything is missing until you have looked.
2. **Polish the site.**
   - Material theme: if `mkdocs.yml` does not already use the Material theme, switch it to Material. If it already does, leave the theme alone and say so.
   - Search: make sure full-text search is on (Material includes it by default — confirm it builds a search index).
   - Version stamp in the footer of every page: add a footer line reading "Fred Lobster Race Rules 2027" with a version/date stamp, using the simplest Material-supported way (for example a footer template override under an overrides directory, or the theme's extra/footer configuration). Keep it to the footer only; do not restyle the rest of the site.
   - Print styling for the quick-reference: add print CSS (in `docs/css/`, wired into `mkdocs.yml`) so `docs/quick-reference.md` prints cleanly on one page — hide the site navigation and sidebar in print, keep the text legible. Verify with a headless Chromium print-to-PDF and confirm it comes out to one page; if it does not fit, tighten spacing and font size for print only until it does.
3. **Build and check locally.** `mkdocs build` must exit clean. Serve locally and verify the home page, a rules page, and the quick-reference all return `200`, and the search index was built.
4. **Publish to GitHub Pages.** Use the repo's existing deploy mechanism if Step 1 of this phase found one (for example a GitHub Actions workflow). Otherwise deploy with `mkdocs gh-deploy` (builds the site and pushes it to the `gh-pages` branch). The deploy target is the **race-rulebook repo only**. Do not create a new repo. Do not touch any other repo. Verify the live link with `curl` and expect `200`. GitHub Pages can take a minute or two after a deploy; wait and re-check if it is not up yet.
5. **Report back and stop.** Report: what was already in place vs what you changed (theme, search, footer stamp, print CSS), the build result, the live public link, and confirmation that search works and the quick-reference prints on one page. Then stop. The owner will review the live book before Phase 2.
